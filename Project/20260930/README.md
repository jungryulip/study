# DAY 55 — 미니프로젝트 II DB 초기 데이터 구성과 메인 페이지 구현

> 2026-09-30 · CBTfy, DB 시드 데이터, 키워드 분류, React, 메인 페이지

오늘은 미니프로젝트 II의 자격증 학습 콘텐츠를 데이터베이스에 넣기 위한 **초기 데이터 구조**를
정리하고, React 프론트엔드에서 메인 페이지를 구현해 화면에 띄웠다. 정보처리기사 학습 키워드를
여러 기준으로 분류해 이후 문제·오답·취약점 분석에 활용할 수 있도록 준비했으며, 메인 화면에는
자격증 검색과 정보처리기사·SQLD·ADsP 카드를 배치했다.

## 1. 오늘의 목표

- 자격증 학습 데이터를 일관된 기준으로 분류하기
- DB에 반복해서 넣을 수 있는 초기 데이터의 형태 정리하기
- 전날 만든 디자인 시스템을 실제 React 화면에 적용하기
- 검색창과 자격증 카드를 포함한 메인 페이지 렌더링하기
- 화면 실행 중 발견한 Router 컨텍스트 오류 확인하기

## 2. DB 초기 데이터 설계

정보처리기사 학습 내용을 단순한 키워드 목록으로 저장하면 서로 다른 의미의 데이터가 섞이기 쉽다.
그래서 키워드가 어떤 성격인지 구분할 수 있도록 분류 기준을 먼저 만들었다.

| 분류 영역 | 포함하는 내용 | 활용 예시 |
| --- | --- | --- |
| 학습 주제 | 소프트웨어 설계, 테스트, 자료구조, 데이터베이스, 운영체제, 네트워크, 보안 | 과목·주제별 문제 묶기 |
| 개발 기술 | 언어, 플랫폼, 개발 기술과 도구 | 기술별 문제 검색 |
| 학습 진단 | 추론 유형, 문제 유형, 혼동하기 쉬운 개념, 암기 유형 | 오답 원인과 취약점 분석 |
| 세부 개념 | 코드, DB, 네트워크, 보안 개념 | 키워드별 복습 자료 연결 |

이렇게 분류하면 같은 단어를 단순 문자열로만 저장하는 대신, 학습 목적과 분석 기준을 함께 관리할 수
있다. 이후 문제에 키워드를 연결하면 사용자가 어떤 영역을 자주 틀리는지 집계하고 복습 화면에 활용할
수 있다.

```text
자격증 → 학습 주제 → 키워드 → 문제 연결 → 응시 기록 → 취약 키워드 분석
```

## 3. 초기 데이터 구성 원칙

- 코드와 표시 이름을 분리해 화면 문구가 바뀌어도 데이터 관계가 유지되게 한다.
- 같은 키워드가 중복 생성되지 않도록 고유한 분류값과 이름을 사용한다.
- 정보처리기사 외에 SQLD·ADsP 같은 자격증도 같은 구조로 확장할 수 있게 한다.
- 초기화·확인·재설정 과정을 반복할 수 있도록 데이터와 실행 흐름을 나눈다.
- DB 계정과 비밀번호 같은 설정값은 데이터 파일에 넣지 않고 환경변수로 분리한다.

오늘은 실제 운영 데이터 적재를 완료한 단계가 아니라, **DB에 넣을 시드 데이터와 분류 체계를
준비한 단계**다. 실제 연결과 전체 데이터 검증은 다음 구현 단계에서 이어갈 예정이다.

## 4. 메인 페이지 구현

현재 구현 화면의 서비스명은 **CBTfy**다. 사용자가 첫 화면에서 바로 학습할 자격증을 찾을 수 있도록
다음 요소를 구성했다.

- 상단 로고와 자격증·학습 메뉴, 회원가입·로그인 링크
- 학습 목적을 설명하는 제목과 안내 문구
- 자격증 이름을 찾기 위한 검색 입력창
- 자격 유형, 시행기관과 콘텐츠 상태를 보여 주는 자격증 카드
- 준비가 된 정보처리기사 카드의 `학습 시작` 버튼
- 준비 중인 SQLD·ADsP 카드와 향후 확장 안내

전날 정리한 색상·타이포그래피·간격·테두리 토큰을 공통 스타일에 반영해, 카드와 입력창이 같은
규칙을 사용하도록 맞췄다. 아직 연결되지 않은 자격증은 버튼 대신 준비 상태를 표시해 사용자가 현재
이용 가능한 범위를 구분할 수 있게 했다.

## 5. 화면 실행 중 확인한 오류

초기 화면에서는 Router 밖에서 라우팅 기능을 사용해 `useLocation()` 관련 오류가 발생했다. 라우팅
컨텍스트와 내비게이션 컴포넌트의 위치를 확인한 뒤 화면을 다시 렌더링했고, 최종적으로 검색창과 세
개의 자격증 카드가 함께 표시되는 것을 확인했다.

오류 화면 자체는 내부 파일 구조가 보이기 때문에 공개하지 않고, 문제의 원인과 해결 과정만 일지에
남겼다.

## 7. 공개 전 보안 점검

- 키워드 원본 PDF는 학습 내용만 요약하고 저장소에는 올리지 않았다.
- 팀 저장소명·브랜치·계정 식별자가 보이는 GitHub와 DB 작업 화면은 제외했다.
- 브라우저 주소, 개발자 도구와 내부 파일 구조가 보이는 오류 화면도 제외했다.
- `.DS_Store`와 중간·중복 화면은 포함하지 않았다.
- 개인정보, 비밀번호, API 키와 DB 접속 정보가 없는 최종 화면 한 장만 공개했다.

## 오늘의 정리

- 정보처리기사 키워드를 주제·기술·학습 진단·세부 개념 기준으로 분류했다.
- 자격증과 문제, 응시 기록, 취약 키워드 분석으로 이어질 초기 데이터 흐름을 정리했다.
- React 메인 페이지에 검색창과 정보처리기사·SQLD·ADsP 카드를 구현했다.
- 공통 디자인 토큰을 실제 화면 구성 요소에 적용했다.
- Router 컨텍스트 오류를 확인하고 최종 메인 화면이 렌더링되는 것을 확인했다.
