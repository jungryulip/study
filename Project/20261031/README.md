# DAY 80 — 날씨 기반 코디 추천과 React 화면 전환

> 2026-10-31 · Personal Project, Spring Boot, React, Weather API, MySQL, Refactoring

오늘은 별도의 수업 대신 개인 프로젝트를 진행했다. GitHub에 실제로 푸시한 14개 커밋을 기준으로
날씨 기반 복장 추천을 단계적으로 구현하고, 저장한 코디와 착용 기록을 연결했다. 이어서 주요
화면을 React로 전환하고 프론트·백엔드의 반복 코드를 공통 구조로 정리했다.

프로젝트 저장소는 비공개이므로 공개 일지에는 저장소 이름과 링크, 원본 코드, 내부 경로와
환경 설정값을 넣지 않았다. 작업 중이거나 아직 푸시되지 않은 로컬 변경도 이번 기록에서 제외했다.

## 오늘 작업의 큰 흐름

```text
기상 예보 연동과 체감온도 계산
  ↓
날씨에 맞는 옷 종류·보유 의류 추천
  ↓
사용자 피드백으로 개인 쾌적 온도 보정
  ↓
저장 코디 CRUD와 실제 착용 기록 연결
  ↓
주요 화면 React 전환과 공통 코드 리팩터링
```

## 1. 날씨 기반 복장 추천 3단계

### 1단계 — 기상 예보와 옷 종류 추천

단기예보에서 시간별 기온·습도·풍속·강수 형태를 받아 사용자가 활동하는 시간대의 날씨를
정리했다. 같은 지역과 발표 시각의 예보를 반복해서 요청하지 않도록 캐시하고, 현재 조건을
바탕으로 체감온도와 추천 옷 종류를 계산했다.

- 풍속·강수·습도를 반영한 참고용 체감온도 계산
- 사용자가 설정한 활동 지역·시간과 야외활동 여부 반영
- 쾌적 온도를 기준으로 반팔·긴팔·겉옷과 겹쳐 입기 제안
- 일교차가 큰 날과 비·눈이 예상되는 날의 보조 안내
- 외부 날씨를 불러오지 못해도 기존 화면이 중단되지 않도록 예외 흐름 분리

날씨 정보는 정답이 아니라 복장 선택을 돕는 참고값임을 화면에 함께 안내했다. 외부 API 기능은
기능 스위치로 분리해 설정이 준비되지 않은 환경에서도 기존 서비스가 계속 동작하도록 했다.

### 2단계 — 내 옷장에서 코디 추천

옷장 항목에 보온 정도, 소매 길이와 방수·방풍 같은 날씨 속성을 기록할 수 있게 했다. 입력을
돕기 위해 이름과 소재를 바탕으로 한 제안값을 제공하되 사용자가 직접 수정할 수 있도록 구성했다.

추천에서는 다음 조건을 함께 비교해 보유 의류 중 어울리는 조합을 골랐다.

- 체감온도에 필요한 보온 수준과 소매 길이
- 비·눈·바람에 대응하는 기능 태그
- 최근 착용 여부와 사용자가 저장한 스타일 취향
- 선택 가능한 옷이 없을 때 보여 줄 종류 예시와 구매 후보 연결

그날 실제로 입은 옷에는 당시 날씨 요약을 함께 남겨, 이후 추천과 실제 착용 경험을 비교할 수 있는
기초 데이터를 만들었다.

### 3단계 — 피드백으로 개인화

추천을 본 뒤 `추웠어요`, `딱 좋았어요`, `더웠어요` 중 하나를 선택하게 하고, 이 응답을 개인 쾌적
온도에 조금씩 반영했다. 같은 날 여러 번 누른 응답이 반복 적용되지 않도록 제한하고, 최근 피드백은
설정 화면에서 확인할 수 있게 했다.

이 과정에서 개인화는 복잡한 모델을 먼저 도입하기보다 **추천 → 실제 경험 → 작은 보정**의 반복으로
시작할 수 있다는 점을 확인했다.

## 2. 홈 화면과 디자인 시스템 정리

홈 화면에는 체감온도, 권장 옷 종류와 우산 여부를 한 줄로 요약한 오늘의 복장 카드를 추가했다.
날씨 조회가 실패할 때는 기존 안내 문구를 유지해 외부 서비스 오류가 홈 전체로 번지지 않게 했다.

케어 영역도 홈에서 빠르게 확인할 수 있도록 요약 패널을 구성했다.

- 사용 중인 제품과 최근 사용 일수
- 오늘 실행한 루틴과 이번 달 사용 완료 기록
- 최근 반응 기록과 상세 화면 이동
- 개별 조회 실패 시 해당 패널만 숨기는 부분 실패 처리

화면마다 반복하던 타일, 카드, 행 링크, 섹션 제목, 버튼과 내비게이션을 공통 컴포넌트로 정리했다.
버튼 크기와 글꼴, 모바일 하단 탭과 데스크톱 상단 내비게이션의 기준도 함께 통일했다.

## 3. 주요 화면을 React로 점진 전환

홈·옷장·오늘의 복장·구매 후보 화면을 React와 Vite 기반으로 전환했다. Spring Boot 컨트롤러가
화면에 필요한 데이터를 JSON 속성으로 전달하고, React가 공통 페이지 틀 안에서 실제 UI를
그리는 구조를 사용했다.

- 고정 내비게이션, 버튼, 카드·타일·행 링크 공통화
- 사진 표시와 이미지 업로드 컴포넌트 분리
- 목록 필터와 요청 처리를 재사용 가능한 함수로 구성
- 화면별 서버 데이터를 명확한 응답 객체로 묶어 전달
- 기존 화면을 한꺼번에 교체하지 않고 기능 단위로 점진 전환

점진 전환을 통해 백엔드 업무 규칙을 유지하면서 프론트 표현 계층을 나눌 수 있었고, 여러 화면에서
같은 디자인과 요청 처리를 재사용할 수 있게 되었다.

## 4. 프론트·백엔드 공통 코드 리팩터링

기능을 늘린 뒤에는 중복을 줄이고 변경 지점을 한곳으로 모으는 작업을 진행했다.

### 프론트엔드

- 공통 레이아웃에서 문자 인코딩, 스타일, CSRF 메타 태그와 공통 스크립트 관리
- 요청 함수에서 CSRF 처리, 버튼 중복 클릭 방지와 공통 오류 문구 통일
- 데이터 속성만으로 저장·삭제를 연결하는 선언형 폼 처리
- 로그인 전 화면에서도 필요한 공통 정적 자원을 불러올 수 있도록 경로 점검

### 백엔드

- 로그인 회원 조회를 공통 서비스로 모아 기능마다 반복하던 코드 제거
- API 오류 생성을 공통 팩토리로 통일
- 흩어진 기능 스위치를 타입이 있는 설정 객체로 묶어 관리
- 시간대 문자열을 직접 사용하는 대신 주입 가능한 `Clock`으로 현재 시각 계산 통일

특히 `Clock`을 주입하면 테스트에서 시간을 고정할 수 있고, 운영 시간대가 바뀌어도 업무 코드 여러
곳을 수정하지 않아도 된다는 장점이 있었다.

## 5. 케어 통계와 이번 주 루틴 기록

케어 통계에는 사용 중인 루틴마다 이번 주에 실제로 실행한 날짜 수를 추가했다. 같은 날 여러 번
실행해도 하루로 계산하고, 월요일부터 오늘까지의 기간 경계를 서비스에서 일관되게 처리했다.
단순 백분율보다 실제 실행 일수를 먼저 보여 주어 기록의 의미를 명확하게 유지했다.

## 6. 저장 코디와 착용 기록

추천으로 끝나지 않고 사용자가 코디를 직접 구성하고 다시 사용할 수 있도록 저장 기능을 추가했다.

- 상의·하의·겉옷 등 슬롯별로 옷을 선택해 코디 생성
- 상황과 코디 이름을 저장하고 목록·상세·수정·삭제 제공
- 보관 처리된 옷, 중복 슬롯과 잘못된 조합을 서버에서 검증
- 동시에 수정한 내용을 오래된 화면이 덮어쓰지 않도록 버전 확인
- 목록·만들기·수정 화면을 React로 구성

저장한 코디에는 `오늘 입음` 기록을 연결했다. 하루 한 번 실제 착용 여부와 상황, 만족도·편안함,
메모를 선택적으로 남기고, 기록 시점의 코디 이름과 구성 옷을 스냅샷으로 보존했다. 코디 착용 기록과
개별 옷의 착용 로그도 함께 연결해 하나의 행동이 관련 기록에 일관되게 반영되도록 했다.

## 7. 추가한 검증 항목

- 날씨 조회 실패와 기능 스위치가 꺼진 환경에서도 기존 화면이 동작하는지 확인하는 테스트
- 추천 규칙과 피드백 기간 경계, 하루 한 번 반영 조건을 다루는 서비스 테스트
- 저장 코디의 생성·수정·삭제와 잘못된 슬롯·보관 옷을 검사하는 테스트
- 착용 기록이 코디 이력과 개별 옷 로그에 함께 연결되는지 확인하는 테스트
- 화면에 전달되는 React 속성과 주요 페이지 표시 여부를 다루는 테스트
- 실제 MySQL을 이용하는 검증과 DB 없이 실행하는 단위·화면 테스트 보강

## 공개 전 보안 점검

- 비공개 개인 프로젝트의 이름·URL과 14개 커밋의 직접 링크는 공개하지 않았다.
- 원본 Java·JavaScript·SQL, 전체 변경 파일과 비공개 저장소 자료를 복사하지 않았다.
- 기상 API 인증키, DB 접속정보, 환경 변수 값, 계정·세션 정보와 개인 로컬 경로를 넣지 않았다.
- 별도로 제공된 공개용 이미지가 없어 비공개 프로젝트 화면을 임의로 캡처하거나 첨부하지 않았다.
- 아직 푸시되지 않은 로컬 변경은 오늘의 일지 내용에서 제외했다.
- 포트폴리오 저장소만 수정하며 개인 프로젝트 저장소에는 어떤 변경도 가하지 않았다.

## 오늘의 정리

- 기상 예보와 사용자 설정을 이용해 날씨 기반 옷 종류 추천을 구현했다.
- 보유 의류의 속성과 착용 이력을 조합해 내 옷장 코디 추천으로 확장했다.
- 사용자의 체감 피드백을 개인 쾌적 온도에 반영하는 작은 개인화 반복을 만들었다.
- 저장 코디 CRUD와 실제 착용 기록, 개별 옷 로그를 하나의 흐름으로 연결했다.
- 주요 화면을 React로 전환하고 공통 UI·요청·오류·설정·시간 처리 중복을 줄였다.
- 단위·화면·MySQL 검증을 보강해 기능 확장과 구조 개선을 함께 확인했다.
