# DAY 53 — 미니프로젝트 II 화면 설계와 기획 발표 자료 작성

> 2026-09-28 · CertMaster, UI·UX 목업, 와이어프레임, 서비스 기획, 발표 자료

오늘은 미니프로젝트 II에서 사용할 자격증 학습 웹사이트 **CertMaster**의 화면을 설계하고,
기획 발표를 위한 자료를 작성했다. 바로 코드를 구현하기보다 러프 스케치와 종이 와이어프레임으로
화면의 정보 구조를 먼저 정리한 뒤, 다크 네이비와 하늘색을 중심으로 고해상도 UI 목업을 만들었다.
또한 문제 풀이부터 복습과 취약점 분석까지 이어지는 서비스 흐름을 발표 자료로 정리했다.

## 1. 오늘의 목표

- 자격증 학습 서비스의 핵심 사용자 흐름 정리하기
- 러프 스케치에서 종이 와이어프레임, 고해상도 목업으로 발전시키기
- `내 학습`과 `키워드별 오답노트` 화면의 정보 우선순위 설계하기
- 문제 선택 전·후 상태와 개인 메모 기능을 화면으로 표현하기
- 서비스 구조, 데이터 흐름과 MVP 범위를 기획 발표 자료로 정리하기

## 2. 스케치에서 UI 목업까지

먼저 손으로 화면의 큰 영역과 이동 흐름을 빠르게 그려 보았다. 러프 스케치에서는 완성된
스타일보다는 어떤 정보를 한 화면에서 보여 줄지, 사용자가 다음 행동을 어디에서 시작할지를
중심으로 확인했다.

그다음 종이 와이어프레임에서 카드, 목록, 필터와 상세 패널의 위치를 구체화했다. 마지막으로
고해상도 목업을 만들며 공통 색상, 여백, 버튼, 배지와 사이드바 규칙을 적용했다. 이 과정을 통해
화면을 곧바로 꾸미기보다 구조를 먼저 검증하면 수정 비용을 줄일 수 있다는 점을 확인했다.

```text
러프 스케치 → 종이 와이어프레임 → 고해상도 UI 목업
```

## 3. 주요 화면 설계

### 내 학습

학습 중인 자격증과 진행 상황을 한눈에 확인할 수 있도록 자격증 카드, 진도와 최근 학습 기록을
한 화면에 배치했다. 사용자가 현재 공부 중인 항목과 다음 행동을 빠르게 찾을 수 있도록 정보의
우선순위를 조정했다.

### 키워드별 오답노트

첫 번째 버전은 목록 중심으로 구성했지만, 문제를 다시 찾고 비교하기에 정보가 부족했다. 두 번째
버전에서는 과목·키워드 필터와 상태 배지를 추가하고 문제 카드를 구분했다. 문제를 선택하면 상세
내용과 해설을 확인하고, 오른쪽 개인 메모 패널에 다시 볼 내용을 기록할 수 있도록 설계했다.

### 상태가 보이는 인터랙션

- 문제를 선택하기 전에는 필터와 목록 탐색에 집중한다.
- 문제를 선택하면 상세 내용과 해설 영역을 함께 보여 준다.
- 정답·오답·복습 상태는 색상과 배지로 구분한다.
- 개인 메모는 별도 패널에서 작성하고 저장 상태를 확인한다.

## 4. 디자인 시스템 방향

전체 화면은 어두운 네이비 배경과 밝은 하늘색 포인트를 사용했다. 사이드바, 카드, 입력창과
버튼의 형태를 반복해 학습 화면과 관리자 화면이 같은 서비스처럼 보이도록 맞췄다. 색상만으로
상태를 표현하지 않도록 텍스트와 배지를 함께 사용하고, 중요한 동작은 충분한 대비를 갖도록
구성했다.

## 5. 기획 발표 자료 정리

발표 자료에는 기능 목록뿐 아니라 왜 이 서비스를 만들고 어떤 흐름으로 동작하는지를 담았다.

1. 여러 학습 도구에 흩어진 문제 풀이와 복습 기록의 불편함을 문제로 정의했다.
2. `문제 풀이 → 채점 → 오답 복습 → 취약점 분석 → 보완 학습` 흐름을 설계했다.
3. 정답 여부와 사용자가 아직 이해하지 못한 상태를 구분하는 복습 규칙을 정리했다.
4. AI는 정답을 결정하는 주체가 아니라 해설과 보완 학습을 돕는 역할로 한정했다.
5. 회원, 자격증, 문제, 응시 기록, 키워드와 취약점 분석을 중심으로 데이터 구조를 구상했다.
6. React, Spring Boot와 Oracle을 연결하는 서버 중심 구조와 단계별 MVP 범위를 정리했다.

발표 자료의 빈 이미지 영역은 실제 화면을 배치하기 위한 자리표시자이므로, 현재 자료는 최종본이
아닌 **기획 발표 초안**으로 구분했다.
