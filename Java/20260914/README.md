# DAY 44 — 리눅스 사용자·권한과 프로세스 관리

> 2026-09-14 · 사용자·그룹 관리, 소유권과 권한, 프로세스 관리

오늘은 여러 사용자가 한 Linux 시스템을 사용할 때 계정과 그룹을 관리하고 파일 접근 범위를
제어하는 방법을 실습했다. 이어서 실행 중인 프로그램을 프로세스 관점에서 살펴보고, 프로세스를
조회·종료하거나 포어그라운드와 백그라운드 사이에서 전환하는 방법을 익혔다.

## 1. 사용자와 그룹 관리

Linux에서는 사용자마다 UID가, 그룹마다 GID가 부여된다. `/etc/passwd`에서 사용자 계정의 UID,
기본 그룹, 홈 디렉터리와 로그인 셸을 확인할 수 있고, `/etc/group`에서는 그룹 정보를 확인할 수
있다. 실제 비밀번호는 이 파일에 평문으로 저장되지 않는다.

```bash
# 그룹 생성과 확인
sudo addgroup animals
grep animals /etc/group

# 지정한 그룹에 사용자 생성
sudo adduser --ingroup animals dog

# 사용자와 그룹 삭제
sudo deluser --remove-home dog
sudo delgroup animals
```

실습에서는 그룹을 먼저 만들고 사용자를 해당 그룹에 추가했다. 사용자를 완전히 정리할 때는 계정만
삭제할지, 홈 디렉터리까지 함께 삭제할지 옵션을 확인해야 한다는 점도 배웠다.

### 사용자 전환

```bash
su dog       # 현재 위치와 환경을 유지하며 dog로 전환
su - dog     # dog의 로그인 환경과 홈 디렉터리로 전환
sudo su      # 관리자 셸로 전환
```

`su 사용자`와 `su - 사용자`는 시작 위치와 환경 변수 적용 방식이 다르다. 관리자 권한이 필요한 한
번의 명령은 `sudo`를 붙이는 방식이 더 명확하며, 실습 후에는 `exit`로 원래 사용자에게 돌아왔다.

## 2. 파일 소유권과 권한

`ls -l`의 권한 문자열은 파일 종류 뒤에 소유자(user), 그룹(group), 그 밖의 사용자(other)의
`rwx` 권한을 차례대로 표시한다.

| 권한 | 파일에서의 의미 | 디렉터리에서의 의미 |
| --- | --- | --- |
| `r` | 내용 읽기 | 내부 항목 이름 확인 |
| `w` | 내용 변경 | 항목 생성·삭제·이름 변경 |
| `x` | 파일 실행 | 디렉터리 진입과 내부 항목 접근 |

### 소유권 변경

```bash
sudo chown dog normal_file
sudo chown dog:animals normal_file
```

일반 사용자가 다른 사용자에게 파일 소유권을 넘기려고 하면 권한 오류가 발생했다. `sudo chown`을
사용해 소유자만 바꾸거나 `사용자:그룹` 형식으로 소유자와 그룹을 함께 바꿀 수 있었다.

### 숫자와 기호로 권한 변경

```bash
chmod 777 greetings   # 모든 사용자에게 rwx
chmod 644 greetings   # 소유자는 rw, 나머지는 r
chmod a+w greetings   # 모든 사용자에게 쓰기 추가
chmod g-w greetings   # 그룹의 쓰기 제거
chmod ug=rw greetings # 소유자와 그룹 권한을 rw로 지정
```

숫자 표기에서는 `r=4`, `w=2`, `x=1`을 더한다. 예를 들어 `644`는 소유자에게 읽기·쓰기를,
그룹과 다른 사용자에게 읽기만 허용한다. 권한을 `000`으로 바꾸면 소유자라도 일반적인 방법으로
파일을 읽을 수 없고, 권한을 다시 부여한 뒤 접근할 수 있었다.

### 디렉터리 권한에서 확인한 점

디렉터리의 읽기 권한은 목록 확인, 쓰기 권한은 내부 항목 생성·삭제, 실행 권한은 디렉터리 진입과
내부 경로 접근에 관여한다. 따라서 디렉터리에 쓰기 권한만 주고 실행 권한을 제거하면 기대한 대로
사용하기 어렵다.

여러 실습 사용자가 같은 디렉터리에서 파일을 읽고 수정해 보면서 소유자·그룹·그 밖의 사용자 중
어느 권한이 적용되는지 확인했다. `chmod go=`처럼 특정 대상의 권한을 모두 제거하면 개인용
디렉터리도 만들 수 있지만, `root` 사용자는 관리 목적으로 접근할 수 있었다.

## 3. 프로세스 조회와 종료

프로그램이 실행되어 메모리에 올라간 상태를 프로세스라고 한다. 각 프로세스에는 PID가 있고,
PPID로 부모 프로세스를 확인할 수 있다. 부모가 자식의 종료 상태를 처리하지 못하면 좀비
프로세스가, 부모가 먼저 종료되면 고아 프로세스가 생길 수 있다는 개념도 학습했다.

```bash
ps                # 현재 터미널의 프로세스 확인
ps -f             # UID, PID, PPID 등을 자세히 확인
ps -ef            # 시스템 전체 프로세스 확인
ps -ef --forest   # 부모·자식 관계를 트리 형태로 확인
ps -ef | more     # 긴 결과를 페이지 단위로 확인
```

### 프로세스 종료

```bash
ps -ef | grep sleep
kill <PID>          # 기본적으로 정상 종료 신호 전송
kill -KILL <PID>    # 즉시 종료 신호 전송
killall -TERM sleep # 이름이 sleep인 프로세스에 종료 신호 전송
```

먼저 정상 종료 신호를 사용하고, 응답하지 않는 프로세스에만 강제 종료 신호를 사용하는 것이
안전하다. `sleep 300`을 별도 터미널에서 실행한 뒤 PID를 찾아 종료하고, 실행 중이던 터미널에
`Terminated` 또는 `Killed`가 표시되는 것을 확인했다.

## 4. 포어그라운드와 백그라운드 작업

포어그라운드 프로세스는 현재 터미널에서 사용자와 상호작용하고, 백그라운드 프로세스는 터미널의
입력을 점유하지 않은 채 실행된다.

```bash
ping -c 3 8.8.8.8  # 지정한 횟수만큼 연결 상태 확인

# 실행 중인 작업을 Ctrl+Z로 일시 정지한 뒤
bg                   # 백그라운드에서 계속 실행
fg                   # 다시 포어그라운드로 전환
```

`ping` 실습으로 `Ctrl+C` 종료, `-c` 실행 횟수 제한, `Ctrl+Z` 일시 정지와 `bg`·`fg` 전환을
확인했다.

## 실습에서 발견한 실수

- 파일을 만들려는 문제에서 `mkdir practice.txt`를 실행해 이름만 `.txt`인 **디렉터리**가
  만들어졌다. 일반 파일은 `touch practice.txt`로 생성해야 한다.
- `chmod go=rw`를 디렉터리에 적용하면 그룹과 다른 사용자에게 실행 권한이 없어 내부 경로에
  접근할 수 없다. 디렉터리에서는 `x`의 의미를 함께 고려해야 한다.
- `chmod`, `whoami`, `sudo` 같은 명령의 철자를 잘못 입력했을 때 오류 메시지와 제안 명령을 읽고
  수정했다.

## 오늘의 정리

사용자와 그룹은 시스템의 주체를 구분하고, 소유권과 `rwx` 권한은 각 주체가 파일과 디렉터리에
할 수 있는 행동을 제한한다. 프로세스 관리에서는 실행 중인 작업을 PID로 식별하고 종료 신호를
선택하거나 포어그라운드·백그라운드 상태를 전환할 수 있었다. 명령을 외우는 것뿐 아니라 파일과
디렉터리에서 권한의 의미가 다르다는 점을 실제 오류와 결과로 확인한 것이 핵심이었다.
